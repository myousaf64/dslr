01 What this project is

The same gradient descent as ft_linear_regression, bent into a classifier.

You sort 400 students into four Hogwarts houses from their course marks. The model is logistic regression, trained by gradient descent, with no machine learning library. Around it the subject wraps a data science workflow: describe the dataset with statistics you wrote yourself, visualize it to decide which features matter, then train and predict.

The conceptual jump from the previous project is small and worth naming precisely. Linear regression predicts a number, so it squares the error. Logistic regression predicts a probability, so it squashes the output through a sigmoid and measures error with log loss. The gradient comes out the same shape either way, which is why the training loop looks almost identical.

What is actually graded

Three things. No function may do the heavy lifting for you: the subject names count, mean, std, min, max, percentile and describe as forbidden. The classifier must reach 98% accuracy, measured with scikit-learn's accuracy score on dataset_test.csv. And the subject says you are evaluated on "your ability to present, explain, and justify your choices" and on being "able to explain the functioning of the machine learning algorithms used".

02 The math

A squashing function, a loss that punishes confident mistakes, and four binary problems standing in for one four-way problem.

The hypothesis

hθ(x) = g(θᵀx)     g(z) = 1 / (1 + e−z)

The sigmoid takes any real number and returns a value strictly between 0 and 1, which lets the output be read as a probability. g(0) = 0.5, and it saturates toward 0 and 1 at the extremes. The decision boundary sits where θᵀx = 0, and because that expression is linear in x, the boundary is always a straight line, or a flat plane in higher dimensions.

The cost

J(θ) = −(1/m) ∑ [ yᵢ log(hθ(xᵢ)) + (1 − yᵢ) log(1 − hθ(xᵢ)) ]

This is the subject's own formula. Read it one case at a time. When y = 1 only the left term survives, and it is -log(h): zero cost for a confident correct answer, growing without bound as h approaches 0. When y = 0 only the right term survives and does the mirror image. So the loss punishes confident wrong answers extremely hard, which is exactly what you want from a probability.

Why not squared error

Squared error applied to a sigmoid output gives a cost surface with local minima, so gradient descent can get stuck. Log loss is convex for logistic regression, so there is one minimum and descent always finds it. That is the real reason for the change of loss, and it is a good answer to have ready.

The gradient, and the surprise

∂J/∂θⱼ = (1/m) ∑ ( hθ(xᵢ) − yᵢ ) xᵢⱼ

Compare this to linear regression, where the gradient was (1/m) ∑ (θᵀx − y) xⱼ. Identical, except that the raw prediction is now wrapped in a sigmoid. The logarithms in the cost and the exponential in the sigmoid cancel each other when you differentiate. That cancellation is why one descent loop serves both projects, and it is the single most satisfying fact in this subject.

One-vs-all

Logistic regression answers yes-or-no questions, but there are four houses. So train four separate binary classifiers and let them compete:

classifierₖ answers: "is this student in house k, yes or no?"

prediction = argmaxk hθₖ(x)

Each classifier sees the same data with a relabelled target: 1 for its own house, 0 for the other three. At prediction time all four give a score and the highest wins. Note the scores are not a probability distribution and do not sum to 1, because the four models were trained independently. For picking a single winner that does not matter, since the sigmoid is monotone and the ordering of the scores is the ordering of the raw θᵀx values.

Standardisation, again

zⱼ = ( xⱼ − μⱼ ) / σⱼ    computed on the training set only

Arithmancy runs to about 50000 while Divination sits near 3. Without rescaling, one feature's gradient dwarfs every other and a single learning rate cannot serve them all, exactly as in ft_linear_regression but now across thirteen features at once. The training mean and deviation are saved into weights.json and reused at prediction time, because a model must never see statistics computed from the test set.

04 Walkthrough

From raw CSV to a house, in five steps.

Step 1. Statistics, written out by hand

def std(xs):
    c = clean(xs)
    m = sum(c) / len(c)
    return math.sqrt(sum((x - m) ** 2 for x in c) / (len(c) - 1))  # sample (ddof=1)
tools.py:51-54

The divisor is len(c) - 1, not len(c). That is the sample standard deviation, and it is the choice pandas makes, so the self-check can compare the two directly. Using the population divisor would fail that comparison, and an evaluator with pandas open would see the mismatch immediately.

def percentile(xs, p):
    """Linear-interpolation percentile (numpy/pandas default), p in [0,100]."""
    c = sorted(clean(xs))
    n = len(c)
    if n == 1:
        return c[0]
    rank = (p / 100) * (n - 1)
    lo = math.floor(rank)
    hi = math.ceil(rank)
    if lo == hi:
        return c[lo]
    return c[lo] * (hi - rank) + c[hi] * (rank - lo)
tools.py:65-76

The percentile is the part people get wrong. There are several defensible definitions; this one is linear interpolation between the two neighbouring order statistics, which is what numpy and pandas do by default. The rank is computed over n - 1 intervals, so p = 0 lands on the first element and p = 100 on the last.

clean() at tools.py:38 drops None before every statistic, so missing cells never poison a mean. The dataset genuinely has gaps: the Count row of describe.py shows between 1557 and 1569 present values per feature, out of 1600 rows.

Step 2. Build the design matrix

def build_X(header, rows, feats, means, stds):
    """Standardised design matrix with bias, imputing NaN with feature mean."""
    idx = {f: header.index(f) for f in feats}
    X = []
    for row in rows:
        aug = [1.0]
        for f in feats:
            try:
                v = float(row[idx[f]])
            except (ValueError, IndexError):
                v = means[f]
            aug.append((v - means[f]) / stds[f])
        X.append(aug)
    return X
logreg.py:17-30

Three jobs in one pass. The leading 1.0 is the bias column, so the intercept becomes just another weight and the training loop needs no special case for it. A cell that will not parse is imputed with the feature mean, which after standardisation is exactly 0, meaning a missing value contributes nothing to the score rather than dragging it in some direction. And every feature is standardised with the scalers passed in, which at prediction time are the ones loaded from the model file.

Step 3. The sigmoid, carefully

def sigmoid(z):
    if z < 0:                       # numerically stable both ways
        e = math.exp(z)
        return e / (1 + e)
    return 1 / (1 + math.exp(-z))
logreg.py:10-14

Mathematically the two branches are the same function. Numerically they are not. The naive 1/(1+exp(-z)) computes exp(-z), which overflows for z around -746 and raises OverflowError. The branch for negative z uses exp(z) instead, which underflows harmlessly to zero. Each branch only ever exponentiates a negative number.

Step 4. Train one classifier, then four

def train_binary(X, y, lr, iters):
    n = len(X[0])
    theta = [0.0] * n
    m = len(X)
    for _ in range(iters):
        grad = [0.0] * n
        for xi, yi in zip(X, y):
            h = sigmoid(sum(t * x for t, x in zip(theta, xi))) - yi
            for j in range(n):
                grad[j] += h * xi[j]
        theta = [t - lr * g / m for t, g in zip(theta, grad)]
    return theta
logreg.py:33-44

This is batch gradient descent, which is what the subject requires for the mandatory part: the entire training set is swept before a single update. h holds the error sigmoid(θᵀx) - y, the gradient accumulates h * xⱼ over all samples, and the whole theta vector is rebuilt in one assignment, which is the simultaneous update. Defaults are lr = 1.0 and iters = 2000, set at logreg.py:47.

def train_ova(X, houses_col, houses, lr=1.0, iters=2000):
    weights = {}
    for house in houses:
        y = [1.0 if h == house else 0.0 for h in houses_col]
        weights[house] = train_binary(X, y, lr, iters)
    return weights
logreg.py:47-52

One-vs-all in five lines: relabel the target as 1 for this house and 0 for everyone else, train, store, repeat. The design matrix X is built once and shared by all four.

Step 5. Predict by argmax

def predict(X, weights, houses):
    out = []
    for xi in X:
        scores = {h: sigmoid(sum(t * x for t, x in zip(weights[h], xi))) for h in houses}
        out.append(max(houses, key=lambda h: scores[h]))
    return out
logreg.py:55-60

Score the sample with all four models and take the largest. The sigmoid here is decorative: it is monotone, so argmax over the sigmoids equals argmax over the raw θᵀx. Keeping it makes the scores readable as confidences.

The lesson hiding in this playground

Two features get you into the high nineties, and that is the trap. The real classifier needs 98% on held-out data, and two features measured over three seeds reach only 96.67%, while all thirteen reach 98.75%. Seeing a clean four-quadrant split here and then learning it is not good enough is the point: a decision boundary that looks convincing is not the same as one that clears the bar.

07 Eval defense

Answer out loud first, then open the block.

The subject asks three visualization questions by name. Those three are guaranteed, so they come first. After that, expect to be asked to explain the algorithm itself, since the subject says you must be able to.

Which Hogwarts course has a homogeneous score distribution between all four houses?

Care of Magical Creatures, which is what histogram.py answers. Its four per-house histograms sit on top of each other: the house means are -0.14, -0.03, 0.00 and -0.09, tiny next to the spread.

Be ready for a sharper follow-up. Measuring homogeneity as between-house variance divided by within-house variance, Arithmancy scores even lower: 0.0007 against 0.0030 for Care of Magical Creatures, with every other course above 0.9. Both are defensible answers and both are far more homogeneous than anything else. Naming both, and saying which statistic you used to rank them, is a stronger answer than naming one.

What are the two features that are similar?

Astronomy and Defense Against the Dark Arts. This is not approximate. Their correlation over the 1537 rows where both are present is -1.000000, and the ratio of the two values is exactly -100 for every student: Astronomy is Defense multiplied by -100. They are the same measurement in different units, which is why the scatter plot is a perfect straight line.

The consequence: one of them is redundant. Dropping Astronomy leaves held-out accuracy at 0.9875, exactly unchanged. That measured number is the proof, and it is better than saying "it should not matter".

From this visualization, which features are you going to use for your logistic regression?

Answer honestly, because the code uses all thirteen. The pair plot shows three things: Arithmancy and Care of Magical Creatures carry no house signal at all, Astronomy and Defense are the same feature twice, and the rest separate at least one house from the others.

So the defensible feature set is the nine or ten that remain. The code keeps all thirteen because it costs nothing measurably: dropping Arithmancy and Care of Magical Creatures leaves accuracy at 0.9875, and dropping Astronomy too leaves it at 0.9875. Standardisation plus gradient descent drives the useless weights small on their own. Care of Magical Creatures ends with a largest weight of 0.158 against 2.027 for Herbology.

The one thing not to say is that you used all of them because you did not look. You looked, the difference measured zero, and you kept the simpler code path.

Explain logistic regression to me.

It is linear regression with the output squashed into the range 0 to 1 and read as a probability. Compute θᵀx, pass it through the sigmoid 1/(1+e⁻ᴢ), and the result is the model's confidence that the sample belongs to the class. Training minimises log loss by gradient descent. The decision boundary is where θᵀx = 0, which is a straight line, so logistic regression is a linear classifier despite the nonlinear squashing.

Why log loss instead of squared error?

Two reasons. Squared error applied to a sigmoid output is not convex, so gradient descent can settle into a local minimum; log loss is convex for logistic regression, so there is exactly one minimum. And log loss punishes confident wrong answers without bound, since -log(h) goes to infinity as h approaches zero, which is the right behaviour for something claiming to output a probability.

Show me the gradient. Why does it look identical to linear regression?

∂J/∂θⱼ = (1/m) ∑ (h(x) - y) xⱼ, where the only difference from linear regression is that h is now sigmoid(θᵀx) rather than θᵀx. It happens because the derivative of the sigmoid is g(1-g), and those factors cancel exactly against the denominators produced by differentiating the logarithms in the cost. The two nonlinearities were chosen to annihilate each other, which is why the same training loop serves both projects.

What is one-vs-all, and do the four scores sum to 1?

Four independent binary classifiers, each asking "is this student in my house, yes or no?", with the highest score winning at prediction time. No, the scores do not sum to 1, because each model was trained separately with no constraint tying them together. That is fine for picking a winner, and it is the honest difference from softmax regression, which does normalise across classes and would be the natural upgrade.

Why standardise, and why with the training statistics only?

Standardise because the features live on wildly different scales: Arithmancy near 50000 against Divination near 3. Without it, one feature dominates every gradient and no single learning rate works for all thirteen.

Use training statistics only because the mean and deviation are part of the model. Computing them from the test set would let information about the test data leak into the predictions, and at deployment there is no test set to compute anything from: samples arrive one at a time. The scalers are saved in weights.json at logreg_train.py:25 and reloaded at logreg_predict.py:20.

How do you handle missing values?

Imputed with the training mean of that feature, at logreg.py:27. After standardisation the mean maps to exactly 0, so a missing value contributes nothing to θᵀx instead of pushing the score in some arbitrary direction. In describe.py the missing cells are dropped rather than imputed, via clean(), which is why the Count row shows values below 1600 and differs from feature to feature.

Why does your sigmoid have two branches?

Numerical stability. The textbook form 1/(1+exp(-z)) evaluates exp(-z), which overflows for z near -746 and raises OverflowError. The branch at logreg.py:11 switches to e/(1+e) with e = exp(z) when z is negative, so each branch only ever exponentiates a negative number and underflows harmlessly to zero instead of overflowing.

Which statistical functions did you write yourself, and did you use any forbidden one?

All of them, in tools.py: count, mean, std, minimum, maximum and percentile, which is exactly the list the subject forbids you from importing. The only imports there are csv and math, and math is used for sqrt, floor and ceil, none of which computes a statistic. pandas appears only in test_dslr.py, as the reference the hand-written statistics are checked against, and in no graded program.

Why is the standard deviation divided by n minus 1?

It is the sample standard deviation. Dividing by n underestimates the spread of the population the sample was drawn from, because the deviations are measured from the sample mean rather than the true mean; n - 1 is Bessel's correction for that bias. The practical reason here is that pandas uses ddof=1, and test_dslr.py asserts agreement with pandas to 1e-6, so the population divisor would fail the self-check.

Which gradient descent variant is this, and what would the alternatives change?

Batch gradient descent: all 1600 samples are swept before a single parameter update. The subject requires it for the mandatory part and lists stochastic and mini-batch descent as bonuses. Stochastic descent updates after every sample, so it takes far more, far noisier steps and usually converges in much less wall time; mini-batch sits between the two. All three minimise the same cost and reach the same place; only the path and the speed differ.

Your accuracy is 98.75% and the bar is 98%. What if the real test set comes in lower?

The margin is thin and worth being honest about. Accuracy converges to roughly 98.2 to 98.8 percent across seeds, which is the ceiling for a linear one-vs-all classifier on this data. More iterations do not raise it, and neither does dropping the collinear or the useless features, both measured at exactly 0.9875. The only remaining lever is nonlinear features, such as products or squares of the existing ones, which would let the boundary curve. That is the change to propose if the real test set dips below the bar.

Why is the bias column a literal 1.0 in the data instead of a separate variable?

So the intercept is just another weight. With a constant 1 prepended at logreg.py:22, θ₀ multiplies it and behaves exactly like every other parameter, so the gradient loop needs no special case and the update formula stays uniform. Without it the classifier would be forced through the origin in standardised space, which would cost accuracy for no reason.

Why is prediction instant when training takes half a minute?

Training is 4 classifiers times 2000 iterations times 1600 samples times 14 weights, roughly 180 million multiply-accumulates. Prediction is 400 samples times 4 classifiers times 14 weights, about 22 thousand. Training is around four orders of magnitude more work, which is why the model is trained once and saved rather than refitted whenever a prediction is needed. That split is the reason the subject asks for two separate programs with a weights file between them.
